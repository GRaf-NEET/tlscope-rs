Локальный explicit HTTP/HTTPS-прокси для отладки дочерних процессов.

TLScope помогает разработчикам инспектировать трафик приложений, которые они запускают через инструмент или явно настраивают на использование его локального прокси. Инструмент предназначен для контролируемых сред разработки и тестирования, а не для скрытого или системного перехвата.

## Описание проекта

TLScope - локальный explicit HTTP/HTTPS-прокси для отладки, написанный на Rust. Он умеет запускать дочерний процесс с proxy-переменными окружения, собирать трафик, который этот процесс отправляет через прокси, и показывать запросы, ответы, TLS-информацию, логи процесса, логи TLScope, фильтры и экспорт в терминальном интерфейсе.

Основной сценарий:

```bash
TLScope run -- ./target/debug/my_application --config test.toml
```

По умолчанию TLScope запускает прокси на `127.0.0.1:8080`, стартует дочерний процесс без shell-склейки аргументов, передает ему proxy-переменные окружения и останавливает прокси после завершения сессии.

TLScope не перехватывает весь системный трафик прозрачно. Целевое приложение должно быть запущено через `TLScope run` или явно настроено на использование TLScope как HTTP/HTTPS-прокси.

## Возможности

- Explicit HTTP-прокси для локальной отладки.
- Поддержка `CONNECT` для HTTPS-трафика.
- Опциональная HTTPS-инспекция через локальный отладочный центр сертификации.
- Инспекция HTTP/2 для HTTPS-соединений, которые согласовали ALPN `h2`.
- Туннелирование HTTP/1.1 WebSocket upgrade после рукопожатия `101 Switching Protocols`.
- Запуск дочернего процесса с переменными `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` и вариантами в нижнем регистре.
- Опциональные CA-переменные окружения для популярных клиентов: `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE` и `NODE_EXTRA_CA_CERTS`.
- Терминальный интерфейс для live-списка запросов, деталей запроса, деталей ответа, TLS-информации, raw-preview, логов процесса, фильтрации и JSON-экспорта.
- Команды управления локальным CA: создать, показать путь, показать fingerprint, установить в Windows и удалить локальные файлы.
- Маскирование чувствительных заголовков по умолчанию, опциональное маскирование JSON/form-полей в теле и явное включение показа секретов.
- Localhost-only интеграционные тесты для прокси, HTTPS-инспекции, запуска процессов и маскирования.

## Безопасность и область применения

Используйте TLScope только для приложений, систем и трафика, которыми вы владеете или на тестирование которых у вас есть разрешение.

TLScope не реализует и не должен использоваться для:

- скрытого перехвата трафика;
- внедрения в чужие процессы;
- ARP spoofing, DNS spoofing, packet injection или сетевого перенаправления;
- автоматического изменения системных proxy-настроек;
- автоматической установки CA во время инспекции трафика;
- обхода certificate pinning;
- отключения механизмов безопасности целевого приложения;
- телеметрии или отправки собранных данных во внешние сервисы.

HTTPS-инспекция раскрывает plaintext-содержимое зашифрованного трафика настроенных тестовых клиентов. Включайте ее только в контролируемом окружении и считайте сессии, локальные CA-файлы и экспорты чувствительными данными.

## Быстрый старт

Открыть интерактивный launcher:

```bash
cargo run
```

Запустить дочернее приложение через TLScope:

```bash
cargo run -- run -- ./target/debug/my_application --config test.toml
```

Запустить собранный бинарный файл напрямую:

```bash
TLScope run -- ./my_application --config test.toml
```

Запустить только прокси и настроить клиент вручную:

```bash
TLScope proxy --listen 127.0.0.1:8080
```

По умолчанию CLI-режимы `run` и `proxy` требуют явного подтверждения перед HTTPS-инспекцией. Введите `inspect`, чтобы включить расшифровку, или нажмите Enter, чтобы туннелировать `CONNECT` без расшифровки. В интерактивном launcher HTTPS-инспекция изначально выключена и включается вручную.

## Настройка

TLScope настраивается через CLI-флаги и интерактивный launcher. Документированного конфигурационного файла проекта сейчас нет.

Общие параметры прокси:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `--listen <addr>` | `127.0.0.1:8080` | Адрес, на котором слушает прокси. |
| `--no-tls-decryption` | `false` | Туннелировать HTTPS `CONNECT` без расшифровки. |
| `--ca-dir <path>` | Platform config directory + `TLScope/ca` | Каталог локального отладочного CA. |
| `--max-body-size <bytes>` | `1048576` | Максимум байт тела, сохраняемых в памяти для запроса или ответа. Трафик все равно пересылается полностью. |
| `--redact` | `false` в CLI, `true` в launcher | Маскировать известные чувствительные JSON/form-поля в телах. Чувствительные заголовки маскируются по умолчанию. |
| `--show-secrets` | `false` | Показывать чувствительные значения в UI и экспортах. Печатает предупреждение. |
| `--save-session <path>` | выключено | Сохранить собранную сессию в JSON при выходе из TLScope. |
| `--allow-external` | `false` | Разрешить non-loopback listener после предупреждения. Используйте только в доверенных тестовых сетях. |

Параметры только для `run`:

| Параметр | Описание |
| --- | --- |
| `--workdir <path>` | Рабочий каталог дочернего процесса. |
| `--env KEY=VALUE` | Дополнительная переменная окружения для дочернего процесса. Можно указывать несколько раз. |
| `--no-extra-ca-env` | Не передавать `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE` и `NODE_EXTRA_CA_CERTS`. |

Proxy-переменные, которые передаются дочерним процессам:

```text
HTTP_PROXY
HTTPS_PROXY
ALL_PROXY
http_proxy
https_proxy
all_proxy
```

Если HTTPS-инспекция включена и дополнительные CA-переменные не отключены, TLScope также передает:

```text
SSL_CERT_FILE
REQUESTS_CA_BUNDLE
CURL_CA_BUNDLE
NODE_EXTRA_CA_CERTS
```

## Примеры использования

Запуск дочернего процесса с типичными параметрами отладки:

```bash
TLScope run \
  --listen 127.0.0.1:18080 \
  --ca-dir ./local-ca \
  --max-body-size 1048576 \
  --redact \
  --env RUST_LOG=debug \
  --save-session session.json \
  -- ./target/debug/my_application --config test.toml
```

Туннелировать HTTPS без расшифровки:

```bash
TLScope run --no-tls-decryption -- ./my_application
```

Запустить прокси, который другие клиенты могут использовать явно:

```bash
TLScope proxy --listen 127.0.0.1:8080
```

Слушать non-loopback интерфейс только если вы намеренно открываете прокси в доверенной тестовой сети:

```bash
TLScope proxy --listen 0.0.0.0:8080 --allow-external
```

Управление локальным отладочным CA:

```bash
TLScope ca create
TLScope ca path
TLScope ca fingerprint
TLScope ca install
TLScope ca install --yes
TLScope ca remove
```

Использовать пользовательский каталог CA:

```bash
TLScope ca --ca-dir ./local-ca create
TLScope run --ca-dir ./local-ca -- ./my_application
```

`TLScope ca remove` удаляет локальные CA-файлы, созданные TLScope, после подтверждения. Команда не удаляет сертификаты из trust store операционной системы.

## API / CLI

Документированный интерфейс - CLI:

```text
TLScope [COMMAND]
TLScope run [OPTIONS] -- <program> [args...]
TLScope proxy [OPTIONS]
TLScope ca [--ca-dir <path>] <COMMAND>
```

Команды:

| Команда | Описание |
| --- | --- |
| `run` | Запускает прокси, стартует дочернюю программу с proxy-переменными окружения и открывает TUI. |
| `proxy` | Запускает только прокси и TUI. Клиенты настраиваются вручную. |
| `ca create` | Создает или загружает локальный отладочный CA. |
| `ca path` | Печатает путь к CA-сертификату. |
| `ca fingerprint` | Печатает SHA-256 fingerprint CA-сертификата. |
| `ca install [--yes]` | Устанавливает CA в Windows Root trust store текущего пользователя. На других платформах сейчас возвращает ошибку. |
| `ca remove` | Удаляет локальные CA-файлы, созданные TLScope, после подтверждения. |

Crate также экспортирует публичные Rust-модули для внутреннего использования и интеграционных тестов. Стабильный library API пока не документирован.

Горячие клавиши TUI:

| Клавиша | Действие |
| --- | --- |
| `Up` / `Down` или `j` / `k` | Выбрать запрос или прокрутить логи. |
| `Enter` | Открыть детали запроса. |
| `Esc` | Вернуться на предыдущий экран. |
| `Tab` / `Shift+Tab` | Переключить вкладки деталей; на экране логов переключить страницы Process/TLScope. |
| `l` | Переключить экран логов. |
| `Home` / `End` | Перейти к самым старым или самым новым строкам логов. |
| `PgUp` / `PgDn` | Постранично прокручивать логи. |
| `/` | Войти в режим фильтра. |
| `Space` | Пауза или продолжение live-обновлений. |
| `c` | Очистить текущую сессию. |
| `e` | Экспортировать JSON в `TLScope-export.json`. |
| `r` | Повторно применить текущий фильтр. |
| `y` | Показать выбранный URL; на экране логов скопировать текущую страницу логов. |
| `?` | Показать справку. |
| `q` | Выйти. Если дочерний процесс работает, выбрать: остановить его или оставить запущенным. |

Примеры фильтров:

```text
method:POST
host:api.example.com
path:/v1/users
status:404
status:>=400
type:json
has:request-body
has:response-body
error:true
tls:false
duration:>500ms
```

Несколько токенов фильтра объединяются логическим `AND`.

Поведение экспорта:

- `e` в TUI записывает JSON-сессию в `TLScope-export.json`.
- `--save-session <path>` записывает JSON-сессию при выходе.
- На уровне кода есть helpers для HAR, text report и cURL export, но документированной CLI-команды для этих форматов сейчас нет.

## FAQ

**TLScope собирает весь трафик на моей машине?**

Нет. TLScope - explicit proxy. Приложение должно использовать proxy-переменные окружения или быть вручную настроено на использование прокси.

**Почему для HTTPS видны только записи `CONNECT`?**

HTTPS-инспекция может быть выключена, локальный CA может быть не доверен клиентом, или клиент может использовать прокси не так, как ожидалось. Включайте инспекцию только в контролируемом тестовом окружении.

**TLScope обходит certificate pinning?**

Нет. Если приложение использует certificate pinning, TLScope показывает возникшую TLS/proxy-ошибку и не пытается обходить защиту.

**CA устанавливается автоматически?**

Нет. Инспекция трафика создает или загружает локальный CA, но установка доверия выполняется явно. `TLScope ca install` может установить его в Windows Root store текущего пользователя после подтверждения.

**Что делать, если порт `127.0.0.1:8080` уже занят?**

Выберите другой listener:

```bash
TLScope run --listen 127.0.0.1:18080 -- ./my_application
```

**Секреты скрываются в capture и export?**

Известные чувствительные заголовки маскируются по умолчанию. Маскирование JSON/form-полей в теле требует `--redact` в CLI-режиме и включено по умолчанию в launcher. `--show-secrets` отключает маскирование и печатает предупреждение.

**Можно ли использовать TLScope с клиентами, которые игнорируют proxy-переменные?**

Только если клиент поддерживает explicit proxy через другой механизм настройки. TLScope не внедряется в произвольные процессы.
